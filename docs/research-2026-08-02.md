# Research: Commonly Used Ubuntu 24.04 Tools & Services (2026)

Web research compiled while scoping which server daemons this toolkit's
`capabilities/service-roles/` should cover. Two passes: a broad "what do
people install on Ubuntu 24.04" sweep, then a narrower pass focused on
server-side/developer tooling (the actual scope this repo cares about,
as opposed to desktop apps).

## Desktop applications (out of scope for this repo, noted for completeness)

- **Browsers**: Firefox (default), Brave, Google Chrome
- **Office**: LibreOffice (preinstalled, MS Office-compatible)
- **Media**: VLC
- **Graphics**: GIMP, Blender
- **Password manager**: Bitwarden
- **Code editor**: Visual Studio Code
- **.deb installer helper**: GDebi (works around App Center's .deb install issues)

## Command-line / developer tools (workstation-level, not services)

A commonly cited "modern CLI toolkit" bundle:
```
sudo apt install micro neovim tmux htop fzf ripgrep bat eza -y
```
- **Editors**: micro (simple), Neovim (full terminal IDE)
- **Multiplexer**: tmux
- **Monitoring**: htop
- **Search/navigation**: fzf, ripgrep, bat, eza
- **Build baseline**: `build-essential`, `make`, `curl`, `ca-certificates`, `libssl-dev`

## Package managers / app stores

- **APT** — base system package manager, preinstalled
- **Snap** — preinstalled; used for Firefox and several Canonical-pushed apps
- **Flatpak** — third-party alternative, popular for sandboxed desktop apps
- **App Center** — Ubuntu's newer unified GUI for snaps/debs

## Server-focused developer tools (the relevant scope)

### Containerization & orchestration
- **Docker** — `docker-ce`, `docker-ce-cli`, `containerd.io`, `docker-buildx-plugin`,
  `docker-compose-plugin` via Docker's official apt repo. De facto standard for
  local dev and CI. → implemented as `capabilities/service-roles/docker`.
- **Podman** — included in Ubuntu 24.04's default repos; daemonless, rootless,
  Docker CLI-compatible.
- **containerd** — lower-level runtime, installed via the Docker repo, needs
  `SystemdCgroup` configured (Ubuntu 24.04's cgroup v2-native kernel helps here).
- **Kubernetes / kubectl** — not in default repos; requires adding the official
  Kubernetes apt repo. A single-node role would only cover kubelet/kubeadm
  prerequisites, not a working cluster — judged out of scope for a simple
  install-and-enable service role.
- **Podman Desktop** — GUI on top of Podman/Docker/Kind; desktop tool, not a
  server daemon.

### Web servers & reverse proxies
- **Nginx** — lowest memory footprint, wins on explicit control.
  → `capabilities/service-roles/nginx`.
- **Caddy** — simplest option, automatic HTTPS out of the box, JSON API for
  CI/CD-driven config. → `capabilities/service-roles/caddy`.
- **Traefik** — cloud-native, watches the Docker socket and auto-configures
  routes; strong fit for ephemeral preview environments. Handles 40k–60k
  req/s but uses more memory than Nginx (in-memory routing state).
  → `capabilities/service-roles/traefik`.

### Databases & data stores
- **PostgreSQL** — already covered (`capabilities/service-roles/postgresql`).
- **Redis** — caching/queueing layer, ubiquitous alongside Postgres.
  → `capabilities/service-roles/redis`.
- **MySQL/MariaDB** — MySQL already covered; MariaDB added separately.
  → `capabilities/service-roles/mysql`, `capabilities/service-roles/mariadb`.

### Language runtime / version managers (workstation-level, not services)
- **mise** (formerly rtx) — 2026's default pick: single Rust binary, replaces
  nvm/pyenv/rbenv/goenv/asdf, native `.tool-versions`/`.nvmrc` support, faster
  shell activation than asdf.
- **asdf** — older polyglot plugin-based manager.
- **nvm** — Node-specific; caveat: shell function, not a shim, so it silently
  no-ops in non-interactive shells (a common CI gotcha).
- **pyenv** — Python interpreter versions only; pair with `pyenv-virtualenv` or
  `venv` for package isolation.
- **rustup**, **SDKMAN** — Rust and JVM-ecosystem equivalents.

### Git hosting / deployment / self-hosted PaaS
- **Gitea** — lightweight self-hosted Git server, commonly run in Docker
  alongside Postgres + Nginx.
- **Coolify** — self-hosted Heroku-like PaaS for deploying apps/containers.

### Security & access
- **Tailscale** — already covered (`capabilities/service-roles/tailscale`).
- **UFW** — Debian/Ubuntu's default deny-by-default firewall wrapper around
  iptables/nftables. Not packaged for RedHat-family distros (they use
  firewalld instead). → `capabilities/service-roles/ufw`.
- **Fail2ban** — monitors logs and auto-blocks IPs showing malicious behavior;
  pairs with a firewall for dynamic protection. → `capabilities/service-roles/fail2ban`.
- **AIDE**, **Lynis**, **OpenSCAP** — file-integrity hashing and hardening/
  compliance scans; not implemented as roles.
- **unattended-upgrades** — auto-applies security patches; not implemented as
  a role (overlaps with the existing `capabilities/update` capability).
- **restic**, **duplicity** — encrypted, deduplicated backup tooling; not
  implemented as roles.

## Reference "2026 composed stack" from research

A commonly cited reference stack for a self-hosted dev/staging server:

> Nginx (or Traefik) reverse proxy → PostgreSQL → Gitea → Coolify, all on
> Docker, with mise for local/CI runtime management.

## Outcome

Scoped down to **"core server daemons only"** — tools with a real systemd
service to install/enable/configure, matching the existing
`mysql`/`postgresql`/`tailscale` role pattern. Implemented as new
service-roles: `docker`, `nginx`, `caddy`, `traefik`, `redis`, `mariadb`,
`fail2ban`, `ufw` (released as v1.5.0). Excluded from this pass: desktop
apps, language version managers (no systemd service to manage), Kubernetes
(cluster setup is out of scope for a single-role install), Gitea/Coolify
(broader self-hosting stack, not core infra), and the file-integrity/backup
tooling listed under Security & access above.
